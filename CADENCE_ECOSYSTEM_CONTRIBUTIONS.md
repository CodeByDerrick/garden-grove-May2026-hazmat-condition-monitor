## Purpose

Use this file to preserve evidence that work in this repository produced a methodology, domain insight, feature pressure, interaction pattern, trust boundary, implementation lesson, or other possible contribution to the wider Cadence ecosystem.

The local repository remains authoritative for its own truth. This register records contribution evidence and routing state; it does not replace local doctrine, strategy, roadmaps, backlogs, decisions, tests, or current-state surfaces.

## Required Boundary

```text
local use and evidence
    -> repository-local contribution entry
    -> explicit review with Derrick
    -> approved minimized routing
    -> destination repository disposition
```

- Local capture is allowed when substantial work produces real transferable evidence or meaningful product pressure.
- A local candidate is not Cadence doctrine, feature acceptance, roadmap scope, backlog authority, or implementation permission.
- Ask Derrick before writing the candidate into another repository or an authoritative Cadence roadmap, feature-shaping, doctrine, backlog, or implementation surface.
- Route only the smallest useful abstraction. Do not export private source data, identifying details, secrets, protected content, or repository material the destination does not need.
- Preserve destination truth by pointer rather than maintaining silent duplicate versions.
- Record `no contribution identified` in a completion report when appropriate; do not create entries merely to satisfy process.

## Entry Shape

For each contribution, record:

- ID and date;
- type;
- local source or task;
- how the repository or its user benefited;
- the minimized transferable candidate;
- evidence posture and limits;
- status;
- approval and destination pointer, when applicable.

Suggested states:

- `LOCAL_OBSERVATION`
- `CADENCE_CANDIDATE`
- `PROMOTION_APPROVED`
- `ROUTED`
- `ACCEPTED`
- `DEFERRED`
- `DECLINED`
- `IMPLEMENTED`
- `VALIDATED`

Implementation is not automatically validation.
